# HCCR Research Package

This package contains the paper-aligned synthetic HCCR study source, frozen configuration, archived outputs, tests, paper-source copy and separate UCI Bike Sharing diagnostic. The current `research_paper/` PDF was not overwritten. All findings are research/simulation outputs, not live fleet recommendations.

## Method and sources

- `forecast.py`, `calibrate.py`, `reserve.py`, `policies.py`, and `study.py` implement direct-horizon forecasts, causal horizon-specific/pooled residual scenarios, the 27-set reserve objective, validation gate, and evaluation policies.
- `routing_eval.py` implements confirmed-demand activation followed by the existing repository OR-Tools optimizer. Forecasts are not passed to the CVRP solver.
- `configs/study_config.json` is the frozen primary configuration. `results/` contains the supplied CSV/JSON outputs and preregistration-derived results.
- `realdata/` contains the separate public bike-sharing diagnostic inputs and runner. Bike rentals are not delivery orders and the source has no routing data.
- `paper-source/` preserves the paper TeX/PDF, references, figures and generated table fragments from the research bundle; it does not replace the separate supplied paper PDF.
- `docs/` contains the source audit, claim ledger, preregistrations, reports and hash manifests.

## Capacity-rule audit

The latest supplied paper defines base capacity as `ceil(kappa * initial-training mean)`, but the imported aggregate result bundle was generated by the supplied `study.py` version using `numpy.round`. That changes 240 of 480 primary seed/regime/region capacities. The simulator's current `capacity()` and single-origin API use ceiling. Existing aggregate CSVs are preserved unchanged and the dashboard labels this provenance mismatch; they are not claimed as a rerun of the corrected formula. A full aggregate regeneration is still required before making paper-exact cost or routing claims.

## Environment

The production `requirements.txt` remains unchanged. Install the research-only Python packages in an isolated environment using `research_hccr/requirements.txt`; the repository's root requirements provide NumPy, OR-Tools, pytest and the backend stack. The archive's reference environment was Python 3.12.3, NumPy 2.4.4, pandas 3.0.2, SciPy 1.17.1, statsmodels 0.15.0 and OR-Tools 9.15.6755.

## Validation and execution

From the repository root:

```powershell
python -m pytest research_hccr/tests -q
python -m research_hccr.verify_claims
python -m research_hccr.run_study --stage all
python -m research_hccr.analysis
```

The invariant and claim-verification checks are substantially cheaper than the complete experiment. The staged runner is resumable but takes tens of minutes across main, model, sensitivity and routing stages. It writes to `research_hccr/results/`; use a copy of the supplied artifact directory if regenerating results that must remain unchanged.

The authenticated API reads frozen summary artifacts at `/analytics/hccr-research`, permits allowlisted CSV/JSON downloads, and recomputes one synthetic test-origin reservation decision at `/analytics/hccr-research/decision`. The Research Analytics page labels synthetic, replication, diagnostic and bike-sharing results separately. The Optimization page's HGFCI advisory remains a separate point-forecast signal.

## Interpretation limits

HCCR versus pooled differences are small and reverse by horizon under persistent shocks. The anticipative mechanism test intentionally uses future information and is diagnostic only. The freshness result's intervals overlap its preselected practical threshold. The UCI Bike Sharing evaluation is one supply-censored public rental dataset, not logistics validation. No operational fleet preparation benefit is established.
